# 验证状态

状态日期：2026-09-17。此文件公开开发阶段的结论与边界，不携带本机原始会话、设备标识、SSID、个人路径或上游凭据。**全功能验收未通过。**

## 已有开发验证

- 主机协议、CRC/去重、四路容量、取消、网关转发、安全握手与管理 API 有自动化测试。
- Windows 原生 USB Serial/JTAG 链路已进行 ESP32 实板测试、双向大块校验、背压、配置回滚及 Wi-Fi 恢复测试。其结论不替代外接 GPIO UART 接线、波特率或 RTS/CTS 验收。
- 已通过本地网关调用真实模型，覆盖 SSE、文件传输及客户端代理任务；供应商不支持的 API 仍返回原始错误。
- 已在安装的 DeepSeek Harness Web 中运行真实会话。standard 27 个工具中的 25 个成功执行，覆盖 skill、plan/build、文件、命令、目标、后台任务、子代理消息/中断/恢复、fork、workflow、单轮 Ralph 及随机图像读取。子代理另执行 `structured_output`。
- 发现四个主会话加四个标题请求造成容量冲突后，添加客户端有界调度。最终 8/8 请求成功，活动峰值 4；中途取消后可继续请求。

以上为特定开发设备、版本和负载下的结果，不是所有模型和客户端的兼容保证。模型工具成功须由真实执行与独立结果验证，不能仅依赖模型声称完成。

## 如何复验

1. 按[构建指南](BUILDING.md)运行无需硬件的检查。
2. 使用可控上游核对状态码、响应体、事件顺序和文件散列。
3. 在独立测试板上进行[硬件验收](implementation/hardware-acceptance.md)，保存自己的脱敏报告。
4. 使用真实模型客户端验证工具闭环；Harness 方法见[集成说明](../integrations/deepseek-harness/README.md)。
