# 面向普通使用者的管理界面设计

日期：2026-09-16。状态：实现依据；本文件是需求、源码契约与参考研究，**不是功能已完成或实测通过的声明**。实施顺序为先修复并验证原生 USB 传输，再落地界面和产品验收。

## 产品目标与参考依据

用户进入页面应能回答三件事：现在能否调用模型、哪里需要处理、如何把客户端接入。正常使用路径不要求理解 JSON、串口帧、配置事务或 GPIO。完整管理能力仍保留，但放在适当层级。

参考确认采用 [Wei-Shaw/sub2api 官方仓库](https://github.com/Wei-Shaw/sub2api)，不采用搜索结果中的同名下游仓库。源码的 [DashboardView.vue](https://raw.githubusercontent.com/Wei-Shaw/sub2api/main/frontend/src/views/admin/DashboardView.vue) 展示摘要卡片、趋势图、快捷操作和筛选；[SettingsView.vue](https://raw.githubusercontent.com/Wei-Shaw/sub2api/main/frontend/src/views/admin/SettingsView.vue) 使用分组标签页、带解释的表单、条件展开和分组保存。这些是本项目采用的交互参考。界面独立实现，不复制源码、品牌或图片；不引入本产品没有的多租户、充值、收费和账户池页面。

核对来源：`internal/config/config.go` 的 10 个主机配置；`firmware/main/management.c` 的 14 个设备配置、状态目录、事务实现；`internal/admin/server.go` 与 OpenAPI；`internal/gateway/statistics.go`；`firmware/main/Kconfig.projbuild`；当前 Web 与免密码设计。

## 页面结构

| 页面 | 用户任务 | 主要内容 |
|---|---|---|
| 总览 | 判断是否可用及性能是否异常 | 可用性横幅、请求和用量卡片、吞吐曲线、Token 组成、设备健康、最近事件、暂停/恢复 |
| 接入应用 | 配置 Cherry Studio、IDE 等软件 | 当前实际 Base URL、一键复制本地 API Key、模型列表、分步接入说明、连接检查 |
| 设备与网络 | 连接设备、配对和换 Wi-Fi | 串口选择、实际传输方式、自动配对状态、Wi-Fi 扫描/手工输入、密码替换、网络详情 |
| 服务设置 | 设置上游和请求行为 | 上游 HTTPS 地址、凭据状态与替换、并发上限、超时；高级折叠本机监听和传输调优 |
| 诊断与维护 | 解决问题和维护 | 可读事件表、诊断导出、固件文件选择与进度、重启；折叠完整配置/状态目录、任务表和危险操作 |

侧栏和卡片不堆技术名词。顶部固定“正常 / 暂停接入 / 设备断开 / 等待配对 / Wi-Fi 未就绪 / 正在维护”状态，附具体下一步。首次使用以同一页面中的检查清单引导“连接设备 → 配对 → Wi-Fi → 上游 → 接入应用”，完成后隐藏；不制作第二套设置入口。

视觉采用浅灰背景、白色卡片、克制的蓝/青色强调、细边框和一致留白。主次标题、单位、状态颜色和数字层次一致。桌面两列图表，小屏折为单列；卡片标题不挤占数据空间。错误有文本和图标，颜色不是唯一信息。按钮保留键盘焦点；表单标签关联输入；图表附可读数值/说明并尊重减少动画偏好。空白、加载、无数据、离线、过期、保存中、失败均有单独状态。

## 配置逐项取舍

层级定义：**常用**直接展示；**高级**按用途折叠；**隐藏**不提供日常编辑，但在完整目录保留名称、实际值/设置状态、只读或不可用原因。所有用户可修改字段有表单；完整目录不能替代常用表单，也不能把密码状态布尔值重新提交为密码。

### 主机配置（10 项）

| 字段 | 实际作用 | 展示与交互 | 验证 / 生效 |
|---|---|---|---|
| `upstream_url` | TLS 上游地址和路径前缀 | 常用：模型服务地址，例 `https://api.deepseek.com`；解释这是服务商地址，区别于客户端本地地址 | HTTPS；无用户名/密码、query、fragment 和 `..` 路径；后续请求生效。只去输入首尾空白，不擅自拼 `/v1` |
| `serial_port` | 后台连接目标 COM 口 | 常用：检测结果下拉，保留“手动输入”；已连接时显示当前实际端口 | 使用 `/ports`；通过 `/connect` 验证后保存，不能仅 PATCH 后声称已连接 |
| `baud` | 电脑 UART 打开参数 | 高级且仅 UART：常见值下拉含 2,000,000，自定义受范围限制；USB 隐藏编辑 | 9,600–3,000,000；不独立修改设备运行速率，连接时参数和已连接协商必须区别 |
| `flow_control` | 电脑 UART RTS/CTS | 高级且仅 UART，并有对应引脚能力时允许 | 当前值与实际连接区分；USB 不适用；已连接双端变更走设备事务 |
| `max_concurrent` | 最多同时执行的请求数 | 常用：1–4 选择，默认 4；说明超过上限立即提示忙碌 | 整数 1–4；后续请求生效，不取消已有请求 |
| `connect_timeout_seconds` | 电脑连接阶段和 TLS 握手等待 | 高级：建立连接超时，秒 | 1–600；后续请求；解释不限制完整回答长度 |
| `header_timeout_seconds` | 等待上游响应头 | 高级：等待服务开始响应，秒 | 1–3,600；后续请求；不能标为首 Token 超时 |
| `idle_timeout_seconds` | 无传输活动等待 | 高级：无数据等待上限，秒 | 1–86,400；后续请求；避免用户以为是整个请求总时长 |
| `api_listen` | 本机客户端 API 监听 | 高级：本机 API 端口，常用接入页只读显示实际地址；需要完整字段能力时提供回环地址选择 | 端口 1–65,535，仅 localhost/回环 IPv4/IPv6；与管理端口不同；保存后重启后台生效 |
| `admin_listen` | 管理界面监听 | 高级：管理页面端口和回环地址 | 同上；显示当前地址和待生效地址；不能保存即跳转至未启动地址 |

### 设备配置（14 项）

| 字段 | 实际作用 | 展示与交互 | 验证 / 生效 |
|---|---|---|---|
| `wifi.ssid` | 设备接入的无线网络 | 常用：扫描列表及手工输入（隐藏网络） | 最多 32 **UTF-8 字节**；正常连接表单要求非空。底层空 SSID 能力放在明确的断开 Wi-Fi 高级动作中 |
| `wifi.password` | 无线网络凭据 | 常用：密码框；已设置时显示“保持现有密码”，显式选择“更换密码”或“开放网络” | 空表示开放；8–63 字节或 64 位十六进制；不 trim 密码；未改则不提交，不回读、不写浏览器存储 |
| `wifi.hostname` | 局域网中的设备主机名 | 高级：设备网络名称 | 1–32 字节，字母/数字/连字符；网络事务 |
| `ip.dhcp` | 自动/手工 IPv4 地址配置 | 高级：自动获取（推荐）/手动地址单选 | 默认为 true；手动选中才展开以下四项 |
| `ip.address` | 静态 IPv4 地址 | 高级、仅手动模式 | IPv4，7–15 字节；设备当前仅在 DHCP=false 时应用此组 |
| `ip.gateway` | 静态 IPv4 网关 | 高级、仅手动模式 | IPv4；与地址/掩码一起提交，提供字段级提示 |
| `ip.netmask` | 静态 IPv4 子网掩码 | 高级、仅手动模式 | IPv4 格式；连续位掩码校验可加强客户端提示，但服务端仍是最终判定 |
| `ip.dns` | 静态模式 DNS 服务器 | 高级、仅手动模式 | IPv4；DHCP 模式不展示成可独立覆盖 DNS |
| `uart.baud` | 设备 UART 生效速率 | 高级、仅能力 `uart_configuration_supported=true` | 9,600–3,000,000；通过双端协商应用、验证、确认；USB 标“不适用”，不显示假的运行速率 |
| `uart.flow_control` | 设备 UART 硬件流控 | 高级、仅 UART 且 RTS/CTS 都存在 | 布尔；缺引脚禁用且解释；与速率在同一事务中提交 |
| `tcp.connect_timeout_ms` | ESP32 TCP 建连等待 | 高级诊断：设备连接等待，显示秒并换算 ms | 1,000–120,000 ms；保留毫秒精度能力；解释它与电脑连接超时为两个边界 |
| `tcp.idle_timeout_ms` | ESP32 TCP 无活动连接等待 | 高级诊断：设备无数据等待，显示秒并换算 ms | 1,000–86,400,000 ms；不能在 UI 中悄悄与主机超时合并写入 |
| `telemetry.interval_ms` | 设备状态缓存的采样频率 | 高级诊断：状态采样间隔；默认 1 秒 | 250–60,000 ms；注明电脑拉取约 1 秒，250ms 不等于 UI 250ms刷新；影响新鲜度阈值 |
| `logs.level` | ESP-IDF 日志级别 | 高级诊断：关闭/错误/警告/信息/调试/详细 | 0–5 对应枚举；不承诺它会扩大独立 `u2_log` 环形事件目录 |

设备表中的全部变更都经当前统一事务进入 pending，并须确认持久化；schema 的 `apply=runtime` 不能被前端解释为无需确认。设备断开时保留已有编辑，禁用提交并说明需先连接，不用默认值覆盖未知真实配置。

### 凭据、构建项与不可调参数

| 项目 | 展示决策 |
|---|---|
| 上游 API Key | 常用替换输入，只显示是否已设置；`POST /credentials`。空输入保持原值，当前 API 不提供删除操作，不能造一个“清空已保存密钥”按钮 |
| 本地 API Key | 接入应用页面有复制/临时显示；仅用户主动操作才 GET `/api-token`；复制完成后无需长驻明文。与上游密钥分开命名，不预加载或写 localStorage |
| 配对用户名/密码 | 未配对时常用；已配对折叠“重新配对”。成功立即清除密码输入；配对是设备授权，不是管理网页登录 |
| 管理会话 / 管理 token | 隐藏。沿用自动本机会话与过期续建，界面不要求用户输入管理密码/token |
| `U2_USB_VALIDATION` | 只读设备信息，展示实际“原生 USB Serial/JTAG”或“UART”，不做运行时开关 |
| `U2_UART_NUM`、`U2_UART_TX`、`U2_UART_RX`、`U2_UART_RTS`、`U2_UART_CTS` | 隐藏在日常设置，硬件详情只读。GPIO 改动需重新构建，值为 -1 明确“未配置” |
| `U2_SPI_MOSI`、`U2_SPI_MISO`、`U2_SPI_CLK`、`U2_SPI_CS` | 完整硬件目录只读并标“预留，当前不可用”；不展示 SPI 连接入口 |
| 固件分区/Flash/PSRAM、最大通道、缓冲硬上限、协议版本/恢复速率 | 只读能力与诊断；无运行配置就没有滑块。不能以手动调队列大小作为普通用户提速入口 |
| Wi-Fi 功率/省电、温度传感器 | 当前只有状态、没有配置 API；不要伪造开关。温度 null 显示“暂未采集”并读取原因 |

## 表单保存与失败恢复

1. 每张表单加载后保留基线；只提交改变的字段。数字框空值为“未填”，不能自动变 0；所有范围使用服务端 schema 复核。每个字段有简短作用、单位和生效时间。重新载入状态不得覆盖正在输入的草稿。
2. 点“保存”展示变更摘要；普通主机参数保存成功后标“后续请求生效”。监听参数标“已保存，重启后台生效”，持续展示实际监听器。当前没有后台 restart API，不做虚假的一键重启；提供停止与重新启动的具体操作说明，或先实现相应生命周期 API。
3. URL 与密钥分别使用 host PATCH 和 credentials POST，不能声称原子提交。可使用各自保存按钮；若集成“保存服务”则显示逐项结果，部分失败只重试失败步骤且保持正确的已保存状态，不能自动回读旧 key 或假装已回滚。
4. 设备变更前检查活跃请求；提示“等待当前 N 个请求结束后继续”，提供暂停新请求但不取消现有回答。后端仍校验冲突并返回 409，不在 UI 隐藏无限等待。
5. 网络/链路应用后显示“正在验证连接”，全局候选配置条有“确认保存”和“恢复原配置”，并显示剩余确认时间。`confirm_deadline_ms` 是设备开机单调时间，**不能与 Date.now() 直接相减**。设备 `config.get` 返回即时 `current_time_ms` 和 `session`，浏览器记录响应接收时刻 `_receivedAt`；剩余时间为 deadline-current_time-接收后的经过时间，并校验配置 session 与新鲜设备状态一致。旧固件缺少即时计时字段时显示“等待获取确认时间”且禁用确认，不用可能缓存 60 秒的 `sample_time_ms` 猜测。刷新页面重新读取 pending 与即时设备时钟后恢复此条。
6. 当前固件确认要求非空 SSID 的 Wi-Fi 已获取 IP，链路切换已结束；UI 只有在同一设备会话、新鲜快照和预期状态验证后才允许确认。自动验证与自动确认可以减少操作，但不得绕过失败状态，也不得把“获得 IP”标为“上游鉴权成功”。超时前未成功则让固件回滚。
7. 应用/确认请求超时具有结果未知性，先 GET `/config` 和状态核对，不直接再次 PATCH 或承诺“没保存”。回滚接口返回只表示已安排，轮询到 pending=false 且生效配置恢复后才显示完成。设备配置、升级和诊断互斥时把 409 转成具体提示。
8. Wi-Fi 扫描结果以 SSID、信号、加密状态显示；扫描失败保留手工输入。扫描和完整配置 schema 只按需获取，不能每秒通过设备拉取大目录占用模型带宽。

## 仪表盘：数据与图形契约

总览不再输出原始 JSON。`/state` + `/events` 为主数据流；`/metrics` 供校验或独立消费者。不要为每个小卡片再开一个设备轮询。完整 JSON 只保留在“诊断详情”，可搜索/复制并保持脱敏。

| 展示 | 数据来源/计算 | 表达与边界 |
|---|---|---|
| 可用性和连接路径 | connected、paired、device.network.connected、llm.paused、host.firmware_upload、错误字段 | “本机代理 → USB/UART → Wi-Fi → 上游”；未经真实上游探测最后一段标“已配置”，不能凭 Wi-Fi 在线画成功 |
| 请求摘要 | llm.requests / completed / succeeded / failed / active / rejected / cancelled | 请求数、活动 N/配置上限、成功率；成功率=succeeded/completed，分母为 0 显示 —；拒绝和中断是失败的细分，不重复堆叠计数 |
| Token 摘要/组成条 | prompt_tokens、completion_tokens、total_tokens、cached_tokens | 输入/输出堆叠；缓存是输入子集，不能另加到总量；usage_reported / usage_missing 明确覆盖范围 |
| 请求趋势 | requests_last_60s 与浏览器收到的时间 | 最近一分钟请求数趋势，不冒充瞬时请求/秒；图表注明页面观察窗口 |
| 传输趋势 | device.link.tx_bytes / rx_bytes 的增量除相邻有效采样时间差 | 双折线，单位 KiB/s；设备 tx=设备到电脑、rx=电脑到设备，图例标方向；协议字节不能标为模型正文 Token/s |
| 内存趋势 | device.memory.internal_free / psram_free；host.heap_bytes 辅助 | 剩余 KiB/MiB 折线；没有 total 就不画百分比使用率或凭空把 8MiB当可分配总量；最低余量/最大连续块进详情 |
| Wi-Fi 状态 | network.ssid / connected / rssi_dbm / address / reconnects | 信号格配 dBm 读数，IP 和重连次数；断开/null不显示 0dBm“强信号” |
| 平均等待/时长 | average_first_byte_ms / average_duration_ms | “平均响应首字节”“平均请求时长”；首字节不是首 Token，时长含网络/队列/流完成，不称模型纯推理耗时 |
| 链路健康 | device.link.crc_errors / framing_errors / retries / duplicates / queue_full / resets / rx_queue_depth；电脑 link counters | 小型健康条+异常列表，区分电脑端/设备端，不相加成同一错误总数；保留累计值和近期增量 |
| 四路连接 | device.network.connections[] | 4 行紧凑表：空闲/连接/传输、目标、双向字节、最近错误；不读取或展示请求正文 |
| 最近事件 | recent_changes、按需 `/logs` | 时间、级别/来源、可读事件、解决操作；保留有界列表，日志刷新不超过设备限速 |
| OTA | ota.active / size / offset / image_state / running_partition | 阶段+真实进度；浏览器上传完成不等于固件验证/启动已确认；重连后复查状态 |

所有 LLM 累计值标“本次后台运行”；当前不存在历史按日数据库、逐模型聚合、费用价格表或每秒实时 Token 回调。不得显示虚假的“今日消费”“每日趋势”“模型分布”或模型 tokens/s。缺 usage 明确未统计，不能当成 0；费用不显示或注明“尚未计算”。Token/HTTP 字节在请求结束时结算，进行中不是实时增长。

可先用浏览器内存保存最多 300 个采样点，标“最近 5 分钟（页面打开期间）”；刷新后历史清空是显式范围。不要写 localStorage。将来需要跨刷新历史应新增后台有界时间序列接口，单独验证持久化/容量。

曲线不跨断线补零或插值成真实测量。设备 session 改变、uptime/sample_time 回退或字节累计变小，重建增量基线并画间隔。重复设备缓存采样不新增速率点。设备 freshness 应结合配置采样间隔（例如 max(5秒, 3×间隔)）和主机收取时间；主机每秒接到相同缓存不等于设备新采样。遥测缺失的最后值淡化并标“上次更新…”，活动请求等主机信息可继续显示。过期状态不得启用危险设备操作。

## 操作到接口的映射

| 操作 | 现有管理 API | 实现注意 |
|---|---|---|
| 自动进入、续建会话 | POST `/session`；当前 `request()` | 保留 HttpOnly/Strict cookie、回环/来源验证；仅明确401拒绝后重试，不重放网络超时的写操作 |
| 总览和更新 | GET `/state`；SSE `/events` | 只保留一个连接、退避重连、旧数据标识；会话恢复后重新读快照 |
| 连接设备 | GET `/ports`、POST `/connect` `{port,baud,flow_control}` | 成功后读取实际传输和配对状态；已连接变更给出当前请求中断说明 |
| 配对 / 断开 | POST `/pair`、POST `/disconnect` | 保存成功清空密码；断开停止后台自动重连，按钮文案要明确 |
| 网络和设备设置 | GET `/config/schema`、`/config`；PATCH `/config` `{device:{...}}`；POST `/config/confirm`、`/config/rollback` | 主机和设备分开事务；倒计时恢复、状态核对 |
| 服务和主机设置 | PATCH `/config` `{host:{...}}`；POST `/credentials` | 分组保存，部分成功不伪装成原子性 |
| 接入说明 | GET `/api-token`（主动复制）；effective_listeners | 本地 Base URL 来自真实监听器；上游 URL/key 不能代替本地参数 |
| 暂停/恢复 | POST `/proxy/pause` `{paused:true/false}` | 暂停仅拒绝新请求，已有回答继续；状态条保持明显 |
| 扫描 / 网络检查 | POST `/diagnostics` `{action:"wifi_scan"/"network"}` | 解析成可读结果；network诊断不能代替真实模型鉴权测试 |
| 导出诊断 / 崩溃 / 任务 | POST `/diagnostics` export/crash_export；GET `/tasks` | 按需加载；浏览器 Blob 下载；机密不进入报告 |
| 日志 | GET `/logs?after=N` | 游标去重、有界显示，不伪造无限历史 |
| 固件维护 | POST `/firmware` binary file | 以主机/设备能力的较小上限校验；当前主机4MiB、设备报告6MiB，不能只按设备上限接收 |
| 重启 / 恢复默认 / 清崩溃 | POST `/device/action` 指定 action | 危险操作独立区域，解释影响和保留内容；不把恢复出厂误称重置上游密钥 |
| 停止后台 | POST `/shutdown` | 明确会终止当前请求；关闭网页不停止后台 |

模型列表与真实连接测试需要额外确认实现边界：网页当前位于管理端口，直接跨端口 fetch 到模型 API 不具备现成 CORS；不应在前端隐式长期持有本地 token 来绕过。建议新增同源管理端点，由后台经同一个受限 Gateway/ESP32 隧道完成 `/v1/models` 检查，返回安全整理的结果。不得使用主机网络直连上游。生产前端不能伪造列表或根据厂商名硬编码“当前可用模型”；测试生成应用户主动触发、显示会产生少量模型用量，返回限长摘要且不存日志正文。

## 完成标准与验证清单

- 10 个主机字段、14 个设备字段、凭据和构建目录均有明确归属；常用操作无 JSON 输入，未知 schema 字段在诊断目录可发现，不悄悄漏项。
- 实机 USB 界面不出现可调波特率/RTS，UART 模拟快照出现协商入口；未连接时不推断 transport。
- Wi-Fi 变更、密码保留/替换/开放网络、静态地址、多字段校验、配置超时回滚、刷新 pending 恢复、保存结果未知均有测试。
- 页面打开无需密码；自动续建、SSE 重连、后台停止后恢复及禁止错误写操作重放全部回归。
- 图表验证正确方向/单位、字节增量、采样重复、断线/重启边界；无请求/无 usage/过期/温度 null 不显示误导数字。
- 每个可见按钮真实接入契约；409、401、403、设备未配对、无网络、上游401/404/429/5xx均有可执行的解释，不直接向用户倾倒整个错误 JSON。

- 报告区分单元/契约/浏览器/实机证据。USB修复前后性能与稳定性使用同一测量口径，UI变漂亮不代替传输验收。
